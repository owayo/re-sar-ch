# 旧モノリシック形式の全世代読み取り

登録済み22形式を直接読む。sysstat 2.2 の `0x015d` は [別の選択列形式](08-packed-legacy.md)。
1.x、3.0〜3.1 など原典未入手の版には、隣接版の配置を推定して割り当てない。

## 実測した配置

オリジナルの `sa.h` にある構造体を Clang の Linux x86_64 / i386 ABI で測定した。
[全フィールドの TSV](legacy-layouts.tsv) は、保存長、型、LP64 / ILP32 のオフセットを記録する。
`wire_size` は本家の書き込み長マクロであり、C の `sizeof` とは限らない。
例えば 3.2.4 のヘッダは 217 バイト、4.0.4 は 229 バイト、4.1.3 の固定統計は 276 バイト。
末尾の構造体パディングを足すと、次のレコードを誤読する。

6.1.2 と 8.1.2 も追加採取したため、実採取は24リリース。Debian 12 / arm64 の隔離コンテナ、
Linux 6.18.35 で各版の `sadc` により2サンプルを記録し、同じ版の `sar -A` と reSARch で描画した。
廃止されたヘッダ、古い C 構文、リンク方式へのビルド互換修正を施すが、保存構造体は変更しない。
ソースの URL / SHA-256 は [全リリース manifest](../../tools/sar-matrix/upstream.tsv) に固定する。
公式ソースとその付属 corpus はリポジトリ外に置く。

その後、公式 Git 全133版と回収済み旧48版の計181版もイメージごとに実採取した。
[測定表](../measurements/upstream-matrix-2026-09-24.tsv) と
[採取ペア](../../testdata/sysstat-live/2026-09-24-official-all/) を収録し、全181版で末尾一致と描画を確認した。
この追加検証は27形式を含み、CentOS固有の `0x1170` は既存のCentOS採取結果で検証する。

`exact=true` は、途中終了・不完全レコードがなく、終了位置がファイル長に一致すること。
フィールド位置や計算値の正しさを単独で保証しない。独立 fixture で全22形式 × long 4/8 ×
LE/BE × 単一/複数CPUの値と境界を検証し、切り詰め、再起動、コメント、互換6書式も確認する。
歴史的な `sar` の列構成・計算を再現するプロファイルではないため、全文一致とは表記しない。

## 境界規則

固定統計 → CPU 別 → 個別 IRQ → PID → シリアル → CPU 別 IRQ → ネットワーク → ディスクの順。
配列の長さはヘッダ件数と世代別の保存長から checked 演算で計算する。

- `0x2168` までは `sa_proc` が最大 CPU 番号。非ゼロなら CPU 配列は `sa_proc + 1` 件。
  `0x2169` からは CPU 件数を保存する。CPU 別 IRQ は古い形式では `sa_proc=0` でも1 CPU分ある。
- 個別 IRQ は `0x2162` まで224件、`0x2163` から256件。
- ディスク配列は `0x2167` まではヘッダ件数に従い、`0x2168` 以降は activity flag も必要。
- 再起動は固定部だけ。種別3の最終統計は `0x2168` 以降。
- コメントは `0x216c` 以降で固定部に重なる。文字列は ILP32 で164、LP64で168バイト目から。
  現行形式のように固定部の後ろへ64バイト追加してはいけない。
- `0x216f` は先頭に8バイトの magic と版情報を持つが、本体はまだ旧形式。

## ABI・時刻・単位

`unsigned long` は8バイトのスロットの先頭4/8バイトを読む。`0x2167` 以前には long 幅がないため
既定8バイトと診断し、ライブラリの `OpenOptions.legacy_long_bytes` で明示できる。
エンディアンは magic から判定する。コメントのオフセットだけは long 幅で変わる。

`0x115a` は epoch を持たない。ヘッダの日付とレコードの時計を UTC と仮定し、時計が戻ると日を進める。
当時のタイムゾーンや夏時間による時計の後退を復元する情報はない。
`0x216e` 以前には正確な sysstat 版と machine もないので不明と表示する。HZ は既定100。

`uptime` は全 CPU の時間の合計。`0x2161` までは CPU 数で割り、`uptime0` を持つ後の世代では
単一 CPU 相当の値を使う。CPU 配列のない旧版の未設定 `uptime0` を使ってはいけない。
`uptime0` のない形式では、現在のモデルに合わせて各サンプルを整数 cs に丸めるため、
本家の「差分を取ってから CPU 数で割る」計算に比べて時間間隔が最大1 tickずれる場合がある。
この世代のレートの完全一致は保証しない。

PAGE の `pgpgin/out` と IO の block 数は **生成 Linux カーネルで単位が異なる**。
Linux 2.4 以降とヘッダから確認できる場合だけ、PAGE=kB / IO=512バイトセクタとして公開する。
2.2 以前・版不明では取得不可にし、診断を残す。古いマニュアルの pages という記述から
ページサイズ倍に変換してはいけない（sysstat 5.0.0 の CHANGES でマニュアルだけが訂正された）。
根拠は sysstat 6.1.2 `man/sar.1` の `-b` / `-B` と `sadc.c` の `/proc/stat` 読み取り。

## フィールドの制限

- 対応した値だけを現在のドメインへ写し、未記録・単位不明は `UnsupportedBySource` とする。
- CPU 別 IRQ 配列は境界を検証して読み飛ばす。個別 IRQ 総数と IRQ 集約は読み取れる。
- PID 統計付きのパイプストリームは拒否する。
- 読み書き別のセクタ数を持たない古いディスク配列は境界だけを検証する。
- 廃止された kernel 指標が現行カーネルで採取できず0になる場合がある。新しいコンテナで
  生成したファイルが読めることと、当時の全指標が採取できることは同じではない。
- 現行形式への `convert` の対象は増やさない。

CentOS のパッチ適用済み版の詳細は [CentOS 3・4・5 の実測](07-legacy-centos.md)、
再実行手順は [全リリースの自動採取](06-live-matrix.md) を参照。
